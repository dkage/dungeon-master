# Formatting Markdown

The user reviews and edits Markdown that Claude writes (plans, documentation) in PhpStorm, which flags long lines and
unaligned tables. A PostToolUse hook (`.claude/hooks/format-markdown.sh`) runs the formatter after every Write/Edit of
a `.md` file, so the file on disk ends up right. Write it close to right anyway, so your next Edit matches what is on
disk and nothing surprises the user.

## Write it like this

- **Wrap prose at 120 columns.** Wrapped list items and block quotes use a hanging indent (2 spaces for `-`, 3 for
  `1.`).
- **A blank line after every heading**, and around fenced code blocks, tables and rules. Never two blank lines in a row.
- **Tables are padded into aligned columns**, with the separator row filled to the column width:

  ```
  | Word     | Meaning        |
  |----------|----------------|
  | Campaign | a project root |
  ```

- Keep table cells short. A table row cannot be wrapped, so a 300-character cell makes a 300-character line. When a
  cell needs a paragraph, use a list or a section under a heading instead.
- Do not break inline code, links or URLs across lines. Do not hard-wrap code blocks.
- End the file with a single newline.

## The formatter

```
python3 .claude/skills/formatting-markdown/scripts/mdfmt.py [--width 120] [--check] FILE...
```

It rewrites the files in place (`--check` only reports). It leaves front matter, code blocks, HTML blocks and link
definitions alone, never joins lines you kept apart, and is idempotent. It reports lines it cannot wrap (wide table
rows, long URLs) on stderr.

Two extra modes, both opt-in:

- `--runts` changes nothing and lists "runt" lines: short leftovers of an old wrap, such as a lone `copy` on a line
  whose sentence carries on in lowercase below. The hook runs it after every formatting pass and hands the result to
  you; fix each one by joining it into the next line with a normal edit.
- `--reflow` joins the lines of every paragraph and list item and re-wraps them. It can merge lines the author kept
  apart on purpose (a bold label above its text), so use it only on a file you own, when asked for a clean-up or
  to remove runts, and read the diff afterwards. The hook never uses it.

Tests for the formatter: `python3 -m unittest -v test_mdfmt` from `.claude/skills/formatting-markdown/scripts`.

Run it by hand when the hook did not fire: a file written through Bash (`cat > x.md`), a file produced by a script, or a
session on a machine without the hook.

## Do not format

- `CHANGELOG.md`, release manifests and anything else generated by release tooling (the hook skips `CHANGELOG.md`).
- A file whose project says its Markdown has another style (an `.editorconfig` or a CLAUDE.md rule). Pass `--width`
  if the project sets a different margin.

## Existing files

The first edit of an old, never-formatted file reformats all of it, so the diff is bigger than the change. Mention it in
the summary ("also reflowed the file to 120 columns"). If a diff must stay minimal (a file under review, a commit that
is meant to be one logical change), say so to the user and offer to put the formatting in its own commit.
